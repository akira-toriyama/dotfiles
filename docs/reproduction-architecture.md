# Reproduction architecture design (nix-darwin + home-manager + chezmoi + 1Password)

Ultimate goal: **even if this PC is discarded, an equivalent environment can be reproduced on a new Mac with a handful of commands.**

Settled policy (decided by the user):

- Foundation for reproduction = **nix-darwin + home-manager (flakes)**
- Secrets = **1Password CLI (`op`) integration**
- Approach = this is core, so go slowly and in stages, with a verification gate at each stage

This document covers design only. Implementation happens in each phase of the roadmap ([roadmap.md](roadmap.md)).

---

## 1. Ownership matrix (who owns what)

> Iron rule: **each file/package is owned by exactly one layer**. chezmoi must not re-manage config that home-manager generates (and vice versa). Duplication is the main cause of operational breakdown.

| Target | Owner | Reason |
|---|---|---|
| CLIs buildable with Nix (jq, gh, ghq, direnv, ripgrep, etc.) | **home-manager** `home.packages` | Cross-platform, declarative |
| GUI apps / cask / Mac App Store | **nix-darwin** `homebrew.casks` / `masApps` | Nix cannot build casks |
| Homebrew itself | **nix-homebrew** module | Makes installing the brew binary reproducible too (optional but recommended) |
| Tools from custom taps (currently only `steipete/tap/peekaboo`) | **nix-darwin** `homebrew.brews` + `taps` | Not in nixpkgs → keep on brew |
| macOS defaults (Dock/Finder/NSGlobalDomain, etc.) | **nix-darwin** `system.defaults` / `CustomUserPreferences` | Reproduced declaratively. system-inventory is the input |
| Program config for zsh / starship / git (has a DSL) | **home-manager** `programs.zsh` / `starship` / `git` | Generated by the DSL. The current `.zshrc` gets rebuilt (see below) |
| App-specific hand-edited dotfiles (chord, facet, halo, wand, claude) | **chezmoi** | No Nix DSL; app-owned raw TOML/JSON. Keep as is |
| Secrets (SSH keys, PATs, tokens) | **chezmoi + 1Password** `onepasswordRead` templates | Not stored in the repo; injected at apply time |
| Opaque assets such as sound effects (dot_local/share/sounds) | **chezmoi** | Binary assets |
| LaunchAgents (border-cycle, etc.) | **chezmoi** (the current run_onchange approach) / system-level ones on nix-darwin | Respect existing assets |

Boundary rule (consistent across multiple sources): **home-manager = packages + program config that has a DSL / chezmoi = hand-edited raw config + secrets**.

## 2. Repository layout (following the budimanjojo/nix-config example)

The **canonical pattern** used by a real-world example of the target stack (278★, Nix flakes + chezmoi together):

```
dotfiles/                       # flake and chezmoi source live in one repo
├── .chezmoiroot   → "chezmoi"  # ★ this is what keeps the Nix files at the root from leaking into $HOME
├── flake.nix  flake.lock
├── system/                     # nix-darwin
│   ├── hosts/generic.nix       #   per-machine entry
│   └── modules/                #   homebrew.nix / defaults.nix / power.nix /
│                               #   launchd-drift.nix / claude-maint.nix / zmk-log.nix
├── home/                       # home-manager
│   └── modules/                #   zsh.nix / git.nix / packages.nix / mise.nix /
│                               #   chezmoi.nix / furrow.nix
├── chezmoi/                    # ★ chezmoi source root (what .chezmoiroot points to)
│   ├── .chezmoiignore  .chezmoiversion
│   ├── dot_config/{chord,facet,halo,wand}/...  # app-owned raw config
│   ├── private_dot_claude/     #   CLAUDE.md / agents / skills /
│   │                           #   modify_settings.json (★ the modify_ script that rewrites live)
│   ├── dot_local/bin/executable_*   # hand-written helpers (claude-work-report-check, etc.)
│   ├── dot_local/share/sounds/...
│   ├── private_Library/private_Containers/...
│   ├── private_dot_ssh/{private_config,create_private_known_hosts}
│   └── run_onchange_after_*.sh(.tmpl)
├── scripts/                    # repo operations scripts (lint / doc_paths.py / claude-md-eval, etc.)
├── docs/  README.md  CLAUDE.md  install.sh  LICENSE
└── .githooks/  .github/  ruff.toml  lychee.toml  _typos.toml  .taplo.toml
```

> This tree is **the actual state as of 2026-07-27** (measured with `ls -A`). The
> `.chezmoi.toml.tmpl` that was originally planned was not adopted (single machine, so no prompting needed — see [roadmap.md](roadmap.md));
> `.chezmoiversion` is placed instead. `.justfile` was closed out as "nothing to put in it = YAGNI".
> `dot_config/{borders,rift,focusfx}` was dropped along with the whole WM stack
> (see "All brews from custom taps dropped" in [roadmap.md](roadmap.md)).

### ⚠️ Important design decision: adopt `.chezmoiroot` (reversal of an earlier decision)

An earlier decision was "skip `.chezmoiroot`, stay flat", but that was made **assuming chezmoi alone**.
Once nix-darwin's `flake.nix` / `system/` / `home/` live in the same repo,
without `.chezmoiroot` chezmoi will try to expand them into `$HOME` (a serious leak).
Every example repo resolves this with `.chezmoiroot=chezmoi`, no exceptions.
→ **Under this goal, adopting `.chezmoiroot` is the correct call. Withdrawing the old stay-flat decision is recommended.**

Migration is just `git mv` of the existing `dot_config/` and friends under `chezmoi/` (destructive, but only once).

## 3. Bootstrap order for a new Mac

```bash
# 1. Xcode Command Line Tools
xcode-select --install

# 1.5 Add a workspace volume (case-sensitive APFS) on the internal SSD.
# macOS default APFS is case-insensitive → it interacts badly with import resolution
# in Linux-derived code and with git case-only renames. Fixed as a Mac-dev-only area.
sudo diskutil apfs addVolume "$(diskutil info / | awk -F': *' '/APFS Container:/ {print $2; exit}')" \
  "Case-sensitive APFS" workspace

# 2. Nix (Determinate Systems installer; already installed the same way)
curl --proto '=https' --tlsv1.2 -sSf -L https://install.determinate.systems/nix | sh -s -- install

# 3. Fetch the flake repository (manual clone, since chezmoi is not installed yet)
git clone <repo-url> ~/dotfiles

# 4. First nix-darwin switch (installs packages, casks, defaults)
sudo nix run nix-darwin/master#darwin-rebuild -- switch --flake ~/dotfiles#<hostname>

# 5. Sign in to the 1Password CLI (prerequisite for resolving chezmoi templates)
op account add --address my.1password.com --email <email>
eval "$(op signin)"

# 6. Apply dotfiles + inject secrets
chezmoi init --apply --source ~/dotfiles

# Updates from here on
sudo darwin-rebuild switch --flake ~/dotfiles#<hostname>   # system/packages
chezmoi apply                                              # dotfiles
```

Key points of the order:
- **Create the workspace volume before Nix** — the path `ghq.root` points at (`GHQ_ROOT=/Volumes/workspace`, declared in home-manager) must exist before darwin-rebuild. Nix creates its own case-sensitive APFS volume for `/nix`, but the user work area is provided on this side.
- **Do chezmoi last** (secret templates fail unless `op signin` has already happened).
- For the implementation, see the `workspace-volume` phase of [install.sh](../install.sh) (idempotent: skips if a case-sensitive area already exists).

### 3.1 Preconditions for unattended execution (always check here when changing things)

`install.sh` is a single-stage **unattended** end-to-end run; `clone` is not split into an attended stage.
There is exactly one basis on which that design holds:

> **1Password must stay unlocked for the entire run.**

The SSH gate (`P-onepassword`) requires a real signature from the 1Password agent, so if it locks
even once during the run, `✓ 完了` is never reached. Worse, **there is no unattended way to recover**
(a new Mac has no Touch ID enrolled and system unlock disabled = the only option is a human typing the password in the GUI).
So this cannot be defended with "give up if it locks"; only with "**do not let it lock**".

Factors that can break this precondition, and the current defenses:

| Breaking factor | Defense | Location |
|---|---|---|
| 1Password's auto-lock timer | Have it turned OFF during preparation | [README](../README.md) preparation step 2 |
| Screen off → lock via `autolock.onDeviceLock` | Wrap the whole run in `caffeinate -dis` | [install.sh](../install.sh), right after the logging prelude |
| Idle system sleep | Same as above (`-i` / `-s`) | Same as above |

**Caution**: `power.sleep.display = 5` in [power.nix](../system/modules/power.nix) is applied
during `darwin-switch`. In other words, **the run itself installs a "screen off after 5 idle minutes" setting**.
Output to the terminal is not HID input, so it does not reset the timer, and with a 20-minute switch in the
middle the screen will certainly go dark. In the 2026-07-20 measurement this is what made `P-onepassword` fail
(screen off 08:06:27 → 1Password locked → the approval prompt timed out at the gate at 08:17:33).

**This precondition was written only in a commit body (`e2ff5a2` / #219), and another PR from the same day
(`e74cbbc` / #220, which introduced `power.sleep`) silently invalidated it.** To avoid repeating the same
incident, any change touching power, lock, sleep, or 1Password settings must be checked against this section.

## 4. Pitfalls and how to avoid them (known in the community)

| Pitfall | Avoidance |
|---|---|
| home-manager and chezmoi both manage `~/.zshrc` | Single ownership. Put zsh on home-manager and do not keep `dot_zshrc` in chezmoi |
| chezmoi expands the flake/modules into `$HOME` | **`.chezmoiroot=chezmoi`** (§2) |
| Existing brew environment conflicts with nix-homebrew | `nix-homebrew.autoMigrate = true` |
| Double management between standalone home-manager and the darwin module | Use **only the nix-darwin module** (`darwin-rebuild` alone) |
| Secrets end up in `/nix/store` (world-readable) | Secrets only via chezmoi `private_*.tmpl` (0600). Do not put them in Nix |
| There is no automatic Brewfile→Nix conversion | Convert manually, name by name. Keep the old `dot_Brewfile` for reference until migration is verified |

## 5. Migration notes from the previous state (historical record; migration is complete)

> ⚠️ **This section is a snapshot from before the migration (2026-05)**. It was written assuming the
> `dot_Brewfile` of the time and the old WM stack, so **do not read it as a description of where things are now**
> (the current layout is the tree in §2; the owning layers are governed by the ownership table in
> [CLAUDE.md](../CLAUDE.md)). It is kept to preserve the reasoning behind the migration decisions.

**To be moved to Nix (from the current `dot_Brewfile`)**

- CLIs available in nixpkgs (jq, gh, ghq, direnv, shellcheck, cmake, act, trash, etc.) → `home.packages`
- casks (chrome, raycast, vscode, etc.) → `homebrew.casks` (karabiner-elements is not adopted and dropped)
- mas → none applicable (PopClip and others dropped as unnecessary. `homebrew.masApps` is unused)
- custom taps (borders=felixkratz, rift=acsandmann, skhd=jackielii, etc.) → `homebrew.brews`+`taps`
- `sleepwatcher (restart_service)` → `homebrew.brews` (the exact option name for service handling needs to be confirmed in the nix-darwin manual)
- macOS defaults (the table in system-inventory) → `system.defaults` / `CustomUserPreferences`
  - ⚠️ The two items flagged in system-inventory (disabling Gatekeeper / skipping the password on wake) need
    **a security re-think before being carried over**. Do not reproduce them casually.
- `run_onchange_install-packages.sh.tmpl` (which runs brew bundle) **loses its purpose** → replaced by `darwin-rebuild`.
  Delete `dot_Brewfile` after the migration is complete and verified (keep it for reference until then).

**To stay in chezmoi (not moved to Nix)**

- `dot_config/{borders,rift,focusfx}` … app-owned raw config
- `dot_claude/settings.json`, `dot_local/share/*`
- `run_onchange_border-cycle.sh.tmpl` (behavior control, not package installation)
- New: `private_*.tmpl` (inject SSH keys etc. via `onepasswordRead`. `known_hosts` is not secret and can stay plaintext)

**zsh rebuild (the current state is broken)**

- The current `~/.zshrc` sources the retired `_/zsh` structure, so **nothing is being read at all**.
- `~/.zprofile` has `brew shellenv` three times over.
- → **Rebuild declaratively from scratch** with home-manager `programs.zsh` (+ starship).
  Discard the old `.zshrc`/`.zprofile`. chezmoi does not own zsh (single ownership).
